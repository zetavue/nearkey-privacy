Local-first • No cloud • No tracking

Data We Handle

NearKey may process the following data types on your device:

  • Master password — used to unlock your local vault
  • Vault entries — account names, passwords, notes, URLs, categories, and custom fields you save
  • Images you choose to import via screenshot OCR
  • KeePass KDBX files you choose to import or export
  • Local sync data generated when you initiate peer-to-peer synchronization

What We Do NOT Collect

  • We do not collect, transmit, or store your passwords, vault contents, or master password on any server.
  • We do not require you to create an online account.
  • We do not include any analytics SDKs, crash reporting services, advertising SDKs, or tracking frameworks.
  • We do not sell, share, or monetize your personal data.

Data Storage & Encryption

  • Your vault is stored locally in an encrypted database (SQLCipher) on your device.
  • The Data Encryption Key (DEK) is stored in the platform's secure storage (iOS Keychain / Android EncryptedSharedPreferences).
  • The master password is never stored in plain text. It is used only to derive the encryption key at runtime.
  • After biometric unlock is enabled, the vault DEK is stored in secure storage and released only after successful biometric authentication. No biometric template, fingerprint image, or face data is ever stored by the app.

Biometric Authentication

NearKey uses the device's built-in biometric system (Face ID, Touch ID, fingerprint) via the operating system's native API. The app receives only a success/failure result. No biometric data is captured, stored, or transmitted.

Camera Access

Camera access is requested only when you use the QR code scanning feature for local peer sync pairing. Camera data is processed entirely on-device to decode the QR code. No camera images are stored or transmitted.

Screenshot Import & OCR

  • iOS: Apple Vision framework — runs entirely on-device.
  • Android: Google ML Kit Text Recognition — the OCR model is bundled with the app and runs entirely on-device. No image data is sent to Google servers.
  • Imported images are held temporarily and deleted after the import flow completes.

Note: The Google ML Kit SDK may collect anonymous usage metrics (e.g., API call counts) per Google's privacy practices. This does not include your images or text content.

Local Peer-to-Peer Sync

  • Sync is initiated only when you explicitly start it and confirm on both devices.
  • Data is transmitted over an encrypted channel (X25519 key exchange + AES encryption) directly between devices — no server is involved.
  • Sync data includes encrypted vault payloads and device metadata (device name, platform, device ID). No plaintext passwords are transmitted.
  • Sync sessions expire after 10 minutes of inactivity.

Cloud Sync

Cloud sync functionality exists in the codebase but is not active in the current release. If enabled in a future update, this policy will be revised accordingly.

File Import & Export

KDBX import/export files are read and generated locally, encrypted with your master password, and saved through the OS file picker or share sheet. NearKey does not transmit imported or exported files to any server.

Children's Privacy

NearKey is not directed at children under 13. We do not knowingly collect personal information from children.

Data Retention & Deletion

  • All data is stored locally until you delete it within the app or uninstall the app.
  • Uninstalling the app removes all locally stored data.
  • We do not retain any of your data on any server.

Your Choices

  • Delete individual vault entries or the entire vault within the app
  • Disable biometric unlock in Settings
  • Decline to use local sync, screenshot import, or KDBX import/export
  • Uninstall the app to remove all data

Changes to This Policy

We may update this privacy policy from time to time. Changes will be reflected in the "Last updated" date. Continued use of the app after changes constitutes acceptance of the revised policy.

本地优先 • 无云端 • 无跟踪

我们处理的数据

NearKey 可能在你的设备上处理以下数据类型：

  • 主密码 — 用于解锁本地密码库
  • 密码库条目 — 你保存的账号名称、密码、备注、网址、分类和自定义字段
  • 你主动选择通过截图导入的图片
  • 你主动选择导入或导出的 KeePass KDBX 文件
  • 你主动发起本地同步时产生的局域网同步数据

我们不收集什么

  • 我们不会在任何服务器上收集、传输或存储你的密码、密码库内容或主密码。
  • 我们不会要求你注册在线账户。
  • 我们不包含任何分析 SDK、崩溃报告服务、广告 SDK 或跟踪框架。
  • 我们不会出售、分享或以任何方式变现你的个人数据。

数据存储与加密

  • 你的密码库以加密数据库（SQLCipher）的形式存储在设备本地。
  • 数据加密密钥（DEK）存储在平台安全存储中（iOS Keychain / Android 加密共享偏好）。
  • 主密码从不以明文存储，仅在运行时用于派生加密密钥。
  • 启用生物识别解锁后，密码库 DEK 存储在安全存储中，仅在生物识别验证成功后释放。应用不会存储任何生物识别模板、指纹图像或面部数据。

生物识别认证

NearKey 通过操作系统的原生 API 使用设备内置的生物识别系统（Face ID、Touch ID、指纹）。应用仅接收成功/失败的结果，不会捕获、存储或传输任何生物识别数据。

相机访问

仅在你使用本地同步的二维码扫描功能时请求相机权限。相机数据完全在设备上处理以解码二维码，不会存储或传输相机图像。

截图导入与 OCR

  • iOS：Apple Vision 框架 — 完全在设备上运行。
  • Android：Google ML Kit 文字识别 — OCR 模型随应用打包，完全在设备上运行，图片数据不会发送到 Google 服务器。
  • 导入的图片仅临时保留，导入流程完成后即被删除。

注意：Google ML Kit SDK 可能按照 Google 的隐私惯例收集匿名使用指标（如 API 调用次数），不包含你的图片或文字内容。

本地设备同步

  • 同步仅在你明确发起并在两台设备上确认后才会进行。
  • 数据通过加密通道（X25519 密钥交换 + AES 加密）在设备之间直接传输，不经过任何服务器。
  • 同步数据包括加密的密码库内容和设备元数据（设备名称、平台、设备 ID），不会传输明文密码。
  • 同步会话在不活动 10 分钟后自动过期。

云端同步

云端同步功能存在于代码库中，但在当前版本中未启用。如在未来版本中启用，本政策将相应修订。

文件导入与导出

KDBX 导入/导出文件在设备本地读取和生成，使用主密码加密，通过操作系统文件选择器或分享面板保存。NearKey 不会将导入或导出的文件传输到任何服务器。
